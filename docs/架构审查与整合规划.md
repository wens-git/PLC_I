# 架构审查与整合规划

日期：2026-11-14。范围：`plc/src` 全部源码、`web/src` 上位机源码。本文只做审查与规划；除登记在“已落实”小节里的注释分区外，未改变控制行为。

| 层 | 对象 | 行数 | 实际职责 |
|---|---|---|---|
| 类型 | 结构体/枚举 13 个 | - | 运行时、配置、请求、Cy 配置、阀型、确认方式 |

## 二、PLC 审查发现

1. **服务端职责过载（严重）**：`功能块_服务端` 595 行同时做扫描初始化、限位/报警汇总、看门狗、复位状态机、网络与内部请求处理、ACK、状态发布。任何一处改动都可能影响其他职责，也无法单独测试。
2. **扫描顺序隐式耦合（严重）**：正确顺序是 `程序_气缸绑定 → 服务端 → 气缸输入映射 → 气缸调度 → 气缸输出映射`。顺序写错不会编译报错，只会表现为“气缸不动”或“读到上一扫描的传感器”。目前只靠注释约束。
3. **旧对象残留（已复核更正）**：初查怀疑 `气缸_到动点/到原点/取消/忙/完成/故障` 仍留在工程里；复核确认重建脚本每次从原始 `FM_XJV1.project` 开始，只创建当前源码对象，删除的源码不会留下对象。此项不成立，保留记录以免重复排查。
4. **状态查询重复（已在 P2 合并）**：`Cy忙/完成/故障`、`Axis_Busy/Done/Error` 各自重复 token 比对，现已收敛为 `Cy状态` 与 `Axis状态`。
5. **配置有效性重复判断**：`程序_气缸绑定` 推导地址与类型，`气缸_配置有效` 再校验一遍容量、重复、延时约束。规则分散在两处，改一处容易漏另一处。
6. **命名体系不统一**：`Axis_*`、`Cy*`、`功能块_*`、`函数_*`、`气缸_*` 五种风格并存，看不出层次。
7. **错误码字面量散落**：4/5/7/9/10/11/14/17/19 等直接写在多个 FB 中，缺少集中定义，新错误码要全文件搜索。
8. **实时与低频混排**：300 ms 发布块里既做快照又做报表，轴/气缸实时状态刷新慢于控制扫描，界面最多滞后 0.3 s。
9. **轴功能块过大**：`功能块_轴` 481 行混合使能、停止、回原、定位、点动、复位、超时、到位校验，修改风险高。
10. **主循环重复样板**：三个轴调用几乎复制粘贴；IO 输出仍保留 `b输出6/7 := FALSE` 的历史写法。
11. **测试与源码字符串强耦合**：测试断言文件名和代码片段，任何重命名都会大面积失败，反过来阻碍重构。
12. **接口对象碎片化**：12 个 3-8 行的函数对象，文件多、查找成本高。

## 三、上位机审查发现

1. **模板超长单行**：`Axes.vue` 单行 2942 字符、`Cylinders.vue` 1947、`Overview.vue` 921。可读性和 diff 质量都很差。
2. **store.js 职责混合**：WebSocket/QWebChannel 选择、超时、通知、状态合并、点动停止都在一个文件。
3. **业务规则分散**：按钮标签在 `cylinder.js`，禁用条件在 `Cylinders.vue`，原因文案在 `protocol.js`，设备状态推断在 `system.js`。
4. **缺少统一设备模型**：轴、气缸、IO、点位的字段各自定义，页面各自判断 `bound/online/alarm`。
5. **单位与精度分散**：0.001 换算、单位文本在多个视图重复。
6. **无视图层组件复用**：表格行、操作按钮组在多个页面重复实现。

## 四、目标架构

### 4.1 分层与依赖方向

```
40_程序    扫描编排、IO 映射、工程配置换算
    ↓
30_服务    协议服务、许可、配置提交、发布
    ↓
20_内核    轴/气缸驱动、调度、看门狗
    ↓
10_接口    业务 API（Axis_*、Cy*）
    ↓
02_配置    保持区、地址表、工程表、映像、运行配置
    ↓
01_类型    DUT/枚举
```

依赖只能向下。程序层不直接碰驱动细节；接口层不直接写输出；内核层不读协议寄存器。

### 4.2 对象职责重划

| 目标对象 | 职责 | 由谁拆分而来 |
|---|---|---|
| `功能块_协议服务` | 命令解析、ACK、SEQ、网络/内部请求分发 | 现服务端区域 5 |
| `功能块_状态发布` | 快照、报警汇总、绑定纪元、系统字 | 现服务端区域 2+6 |
| `功能块_复位编排` | 停止→静止→复位→完成 | 现服务端区域 4 |
| `功能块_通讯监护` | 签名、心跳、HMI 在线、点动租约 | 现看门狗 + 区域 3 |
| `功能块_轴` | 保持现状，内部再分“使能/运动/停止”三个私有区 | 现 481 行 |
| `Cy状态` | 一次查询返回 忙/完成/故障 | 合并 Cy忙/完成/故障 |
| `Axis状态` | 一次查询返回 忙/完成/错误 | 合并 Axis_Busy/Done/Error |

### 4.3 命名规范

- 接口：`Cy动点`、`Axis_Home` 保留现有风格，不再新增第二种前缀。
- 内核：`功能块_*`、`函数_*`。
- 程序：`程序_*`。
- 配置：`全局变量_*`、`结构体_*`、`Cy*` 枚举。
- 错误码集中到 `全局变量_错误码.gvl.st`，FB 只引用常量。

### 4.4 扫描顺序固化

主循环固定为：配置换算 → 输入读取 → 模式机 → 轴驱动 → 气缸输入映射 → 气缸调度 → 气缸输出映射。顺序写入 `程序_主循环` 顶部注释与架构文档，测试增加顺序断言。

## 六、已落实

P0（分区）：
- `功能块_服务端` 增加 6 个区域标记，明确各段职责与边界。
- `程序_主循环` 增加 5 个区域标记，固化扫描顺序。

P1（集中错误码）：
- 新增 `全局变量_错误码.gvl.st`，`ERR_*` 常量覆盖 0..28 拒绝码。
- `函数_动作许可` 的 60 处数字改为常量引用，行为不变。

P2（合并状态查询）：
- `Cy忙/Cy完成/Cy故障` 合并为 `Cy状态(设备)`，返回 `结构体_Cy状态`（忙/完成/故障）。
- `Axis_Busy/Axis_Done/Axis_Error` 合并为 `Axis状态(轴号)`，返回 `结构体_Axis状态`（忙/完成/错误/错误码）。
- 令牌比对只保留一处；对象由 12 个接口函数收敛为 8 个。
- 更新 `机器人轴接口.md`、`气缸配置与业务接口.md` 与轴接口自测源码。

复核更正：重建脚本每次都从原始 `FM_XJV1.project` 开始，只创建当前源码里的对象，因此不存在旧对象残留问题；此前“工程里仍有旧接口对象”的判断不成立。

## 七、不在本轮做

- 服务端拆分与轴功能块拆分：属于 P3，必须有 PLC 仿真序列测试支撑，否则无法证明行为等价。
- 上位机模板重排：属于 P4，会改动多个视图，需要浏览器联调。
- 现场接线与模块诊断：仍是硬件接入工作，不由软件重构替代。
