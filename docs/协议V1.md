# XJV1 协议 1.3

状态：2026-11-13 气缸/真空接口升级。当前签名 **0x584A5633**，与1.2不兼容，必须配套部署PLC和上位机。寄存器窗口及总量不变；气缸参数第7字由旧未开放的flags变为home_delay_ms，提交掩码4改为原点/释放延时。delay_ms为动点/吸附延时；类型与接线仍工程只读。两侧分别按有传感器连续有效后延时、无传感器动作开始后计时确认。详细模式、迁移和业务接口见[气缸配置与业务接口](气缸配置与业务接口.md)。以下1.2对比表仅保留为历史沿革，不是当前签名。
本文是协议的文字说明。精确地址、字段宽度、字段掩码、报警码表和拒绝文案以 [protocol-v1.json](protocol-v1.json) 为准，完整展开表见 [register-map.md](register-map.md)（由 `python tools/check_protocol.py --write` 生成，请勿手改）。修改 JSON 时，必须同时更新本文、生成表、PLC 常量、后端/前端以及契约测试。

## 1. 传输与数据编码

- Modbus TCP，端口 **1502**，Unit ID 1。PLC 侧使用官方 CODESYS ModbusTCP Slave 设备（设备名 `ModbusTCP_Slave_XJV1`），上位机使用官方 pymodbus `ModbusTcpClient`。**禁止**自行拼装或解析 Modbus TCP 报文，**禁止**在 PLC 中实现自制 socket 从站。本项目只负责业务寄存器映射、命令校验和事务逻辑。
- 两个独立数据区，均为零基 PDU 地址：
  - **Holding Register**：0..31，主站用 FC03 读、FC06/FC16 写，只放命令区。从站参数 `UpdateableHolding = FALSE`，即 PLC 应用只读不写。
  - **Input Register**：0..1829，主站只能用 FC04 读，主站无法写入，由 PLC 的 `FB_XJV1_Server` 独占写入。
- 字内为网络字节序，大整数高 WORD 在前：DWORD `0x584A5633` 对应两个寄存器 `[0x584A, 0x5633]`。DINT 为二进制补码。
- 位置/距离为 DINT，单位为工程单位的 0.001；速度、加减速度为 UDINT（0.001 单位/秒、0.001 单位/秒²）。合法速度范围为 1..2147483647，PLC 还会按额定上限再检查一次。界面输入最多三位小数，不得静默截断。
- 单次 FC03/FC04 最多读 125 字，单次 FC16 最多写 123 字，跨块按此分段读写。
- 整个上位机只有一个后台通信 Worker 持有 Modbus 连接，一次只允许一个普通事务在途。浏览器不直接访问 PLC。所有动作许可集中在 PLC 的 `F_XJV1_ActionPermit`。

## 2. 寄存器预算与窗口

| 区域 | 数量 | 地址范围 | 字节数 | 用途 |
|---|---:|---:|---:|---|
| Holding Register | 32 WORD | 0～31 | 64 | 上位机命令区 |
| Input Register | 1830 WORD | 0～1829 | 3660 | PLC 状态、I/O、实时数据、参数、点位 |
| 名称区 | 0 WORD | 无 | 0 | 上位机管理 |
| **合计** | **1862 WORD** | | **3724** | |

PLC 数组定义（`plc/src/02_gvl/GVL_XJV1_Modbus.gvl.st`）：`Holding : ARRAY[0..31] OF WORD; Input : ARRAY[0..1829] OF WORD;`，两者都不加 RETAIN，因为上电后不得重放命令。

| 窗口 | 区 | 地址 | 步长 × 数量 | WORD |
|---|---|---|---|---:|
| 命令 | Holding | 0～31 | 32 × 1 | 32 |
| 状态 | Input | 0～103 | 104 × 1 | 104 |
| I/O | Input | 104～123 | 20 × 1 | 20 |
| 轴实时 | Input | 124～379 | 16 × 16 | 256 |
| 气缸实时 | Input | 380～541 | 3 × 54 | 162 |
| 轴参数 | Input | 542～797 | 16 × 16 | 256 |
| 气缸参数 | Input | 798～1229 | 8 × 54 | 432 |
| 点位池 | Input | 1230～1829 | 5 × 120 | 600 |

`tools/check_protocol.py` 冻结了上述预算：Holding ≠ 32、Input ≠ 1830、出现 names 窗口、命令表含 51、端口 ≠ 1502 中任一情况都会报错。

**与旧方案比较：** 旧方案仅名称区就占 190 × 8 = 1520 WORD（3040 字节），总跨度 3382 字；现方案 1862 字，节省 1520 WORD，约 44.9%。

**读取频率建议：** 实时部分（状态 + I/O + 轴实时 + 气缸实时 = 542 WORD，约 5 次 FC04）按 100 ms 轮询；参数与点位（1288 WORD）只在 `config_epoch` 或绑定身份变化时重读。1830 WORD 适合监控和参数管理，不能作为硬实时运动控制通道。

对象字：高字节为类型（0 系统、1 轴、2 气缸、3 点位），低字节为索引。非法类型或索引返回 15；索引合法但对象未绑定返回 4。

## 3. 点位池编码

每槽 5W：+0..1 位置（掩码 bit0）、+2..3 速度（掩码 bit1）、+4 标志（掩码 bit2）。

| 标志值 | 含义 |
|---|---|
| bit0 | 启用（必须同时已示教） |
| bit1 | 已示教（只有命令 31 可以置位） |
| bit2..5 | 归属轴 0..15 |
| **0x0040** | **空闲槽**：仅 bit6 置位，其他位全 0 |
| 其他位 | 必须为 0；bit6 与任何其他位同时出现都非法 |

- 轴 15 的点位标志为 `15 << 2 = 0x003C`，空闲槽为 `0x0040`，两者不再冲突。
- 空闲槽可以通过命令 31（示教，对象为轴，A 为槽号）认领，也可以通过命令 50（写入新归属）认领。
- **释放**：用命令 50 将标志写为 0x0040。要求该点位未启用且未示教。轴 i 的待机点 P0（槽 i）**永不释放**。界面"释放"按钮会同时删除该槽在上位机中的别名。
- 冷启动默认值：槽 0..15 分别归属轴 0..15 作为 P0，槽 16..119 为空闲。

## 4. 命令、提交与 ACK

命令区偏移：+0..1 HMI 签名，+2 HMI 心跳（每 800 ms 递增），+3 命令码，+4 提交序号 SEQ，+5 对象字，+6..11 参数 A/B/C（各占一个 DWORD），+12..14 点动续租（计数/对象/启动 SEQ），+15 保留，+16..31 为 16W 提交缓冲。

提交顺序：
1. 读取一个一致的状态快照，取得 ACK 纪元基线。读不到一致快照就不发送命令。
2. FC16 写 +5..11，FC16 写 +16..31，FC06 写 +3。此时 +4 不变，PLC 不会执行。
3. 以上所有写入都成功后，用 **FC06 单独写新 SEQ 到 +4**。SEQ 取值 1..65535，65535 之后回到 1。
4. PLC 在扫描边界发现新 SEQ 后，**一次性复制整个命令块**，依次做签名/结构/对象校验和唯一动作许可判定，执行一次或拒绝。无论成功还是拒绝，都推进 ACK 纪元并写入 ACK SEQ/对象/结果。**ACK = 0 只表示已受理，不表示动作完成。**
5. PLC 上电或 HMI 重新在线时，把 Holding 中残留的 SEQ 当作已消费的基线，**不会执行**。
6. 1 s 内没有匹配的 ACK，标记为"结果未知"，不自动重试。

停止命令（9/10/26/42）会抢占普通队列中尚未发送的命令；已经发送的普通命令标记为"被停止抢占，结果未知"。

## 5. 状态区、报警与诊断

状态区各字段的偏移以 register-map.md 为准。要点：
- +0..1 签名固定为 0x584A5632；+7 系统字；+8 容量字 0x3610；+99 绑定纪元；+100 配置纪元（参数或点位修改成功后 +1，**改名不改变它**）；+103 快照纪元，发布期间为奇数、发布完成后为偶数。
- 上位机读快照时，前后各读一次 +103，两次相等且为偶数才接受；配置区按 `config_epoch` 前后比较。

**报警具体到问题：** 轴实时 +8 和气缸实时 +2 是报警码，轴实时 +9..10 是驱动器错误码。protocol-v1.json 的 `alarms` 表为每个报警码给出具体原因和处理方法，例如：

| 码 | 具体问题 | 处理 |
|---|---|---|
| 1103 | 硬急停触发：轴已被强制断使能并清除回原状态 | 排除急停原因、复位并重新回原 |
| 1134 | 限位阻止动作 | 将轴移出限位，核对目标位置与限位方向 |
| 1143 | 到位校验失败：实际位置与目标的偏差超出容差 | 检查机械间隙、丢步、编码器和缩放参数 |
| 2140 | 气缸动作超时：超时时间内未到达目标传感器 | 检查气压、电磁阀、气缸卡滞和目标传感器 |

完整列表见 register-map.md 的 Alarms 一节。契约测试会检查 PLC 源码中出现的每个报警码都已登记在表中。

上位机诊断页和事件历史的记录内容如下：
- **命令**：例如"使能 · 轴 4：被拒绝（4 对象未绑定）"，并附处理建议、SEQ 和来源。
- **报警的产生和解除**：报警码、对象（含上位机名称）、具体原因、处理方法；轴报警还附带驱动错误码和限位状态。
- **通信**：断线的具体原因（例如签名不匹配时，同时给出实际签名和期望签名；某个对象的数据非法时，给出对象编号和非法值）以及恢复建议。

## 6. 名称（上位机管理）

- 名称是显示元数据，**不占任何 PLC 寄存器**，不参与安全判断、运动控制或参数提交。
- 存储位置：`%LOCALAPPDATA%\FM_GPTPRO\names.json`。写入方式是先写临时文件再原子替换，并保留上一版本为 `names.json.bak`。文件损坏时自动从备份恢复；备份也不可用时显示默认名称，并在诊断页提示。
- 名称的键为"设备档案 + 对象类型 + 索引"。模拟器档案固定为 `mock`；真实设备的档案默认为 `IP:端口/站号`，也可以在连接时指定 `profile`。每个档案同时记录写入时的 PLC 绑定纪元；纪元变化时界面提示"名称可能对应旧硬件"，但不会自动删除名称。
- 名称长度为 1..32 个字符，不能含控制字符或孤立代理项。未命名对象显示默认名称"轴 N / 气缸 N / 点位 N"。
- 修改名称时**没有任何 Modbus 写入**：不使用命令区、不发命令 51、不改变 `config_epoch`、不需要 PLC ACK、不写保留区、不读回名称寄存器。接口需要有效会话，并通过 `revision` 检测多个终端同时修改的冲突。

## 7. 多上位机

- 同一个 PLC:1502 可以被多个客户端连接（并发上限取决于目标运行时，需要在现场核实），**但命令区只有一套 SEQ/ACK/心跳/点动续租**。
- 规定：多个浏览器/终端访问**同一个**上位机后端，由唯一的通信 Worker 串行写入 PLC。其他直接连接 PLC 的客户端只能读取。不要让两台独立的上位机同时向同一个 PLC 写命令。改用不同端口也无法解决命令区冲突。
- 如果现场必须由多台独立上位机直接控制，需要另立任务，在 PLC 侧实现可以强制执行的写者仲裁。

## 8. 心跳、在线与点动租约

内容与 V1.1 相同：PLC 心跳每 200 ms 变化一次；HMI 每 800 ms 写一次心跳；PLC 1.5 s 未见 HMI 心跳变化即判 HMI 离线，并撤销远程点动。点动使用独立续租：每 200 ms 用一次 FC16 写 +12..14，PLC 侧租约 1.5 s；浏览器按住证明超过 400 ms 未刷新时，后端发送 26。恢复连接后不会恢复点动。

## 9. 保持区升级

1.3识别1.2签名0x584A5632，保留轴与点位参数，将气缸旧未开放flags替换为原点延时（取原delay_ms），清除配置确认，并以工程配置覆盖气缸类型和I/O。其它未知签名仍冷初始化。升级前应备份现场工程及参数；1.3不能直接降级使用1.2解释新的第7字。1.1到1.2曾删除Names，属于更早的非兼容布局，不适用本次迁移。

## 10. 拒绝码

拒绝码 0..28 的中文文案和操作建议见 register-map.md。0..19 是通用拒绝；20..28 把原先笼统的 9（参数超出范围）按具体原因细分：20 定标标志、21 软限位、22..25 额定速度/加速度/减速度/停止减速度、26 P0 位置、27 目标越限、28 速度无效。每条文案都写明原因，action 写明处理办法。网络异常和"结果未知"属于上位机传输状态，不伪造成 PLC 拒绝码。

### 软件急停解除（命令11）
物理急停释放且HMI在线时允许清除软件急停锁存；解除不自动启动、不恢复旧动作、不清除待复位状态。报警1103只表示硬急停（X3）有效。本程序不设安全验收开关，也不再产生“安全未就绪”这一拒绝原因。
