## 二、P0：现场阻塞项

### 1. 气缸模块在线位没有写入者（已处理）

`b气缸输入模块在线` / `b气缸输出模块在线` 原本全工程只读不写，`ab气缸模块就绪` 恒 FALSE，气缸永远拒绝 5。

处理结果：在 `全局变量_运行配置` 增加两个工程开关：

- `b气缸IO已接入`：接线核验后置 TRUE，作为未接诊断时的就绪依据；
- `b气缸IO模块诊断已接入`：接好真实模块诊断后置 TRUE，改由在线位判定。

`程序_气缸输入映射` 按“诊断优先、开关兜底”推导就绪。默认两者 FALSE，气缸保持离线；这仍然是调试级开关，不替代真实模块诊断。

### 2. 硬限位输入没有写入者

`ab正限位` / `ab负限位` 只在主循环作为实参传入，从未赋值，恒 FALSE。

后果：`功能块_轴` 里所有硬限位判断永不成立，实际保护只剩软限位和驱动器自身限位。许可层已经加了“软限位关闭且硬限位未接线则拒绝运动”的门禁，但这只能防误配置，不能提供硬限位保护。

处理：接真实限位输入，或明确删除这些形参并在文档声明“只有软限位保护”。

### 3. 物理 IO 尚未映射

- 现场只有 X0..X4、Y6/Y7 声明，气缸输入/输出映像（7 WORD/4 WORD）没有任何设备树映射。
- 因此 `aw气缸输入映像` 恒 0、`aw气缸输出映像` 写出去也没有接收方。

这是硬件接入工作，软件只能提供唯一入口；接入前气缸保持离线是正确行为。

## 三、P1：架构问题

1. **服务端职责过载**：`功能块_服务端` 595 行同时做初始化、限位报警、看门狗、复位编排、命令处理、状态发布。已加 6 个区域标记，但拆分（P3）仍需仿真验证。
2. **扫描顺序隐式**：`绑定 → 服务端 → 输入映射 → 调度 → 输出映射` 仅靠注释和文档约束，写错不报错。
3. **轴功能块过大**：481 行混合使能/停止/回原/定位/点动/复位/超时。
4. **配置有效性两处判断**：`程序_气缸绑定` 推导、`气缸_配置有效` 再校验，规则分散。
5. **测试是源码字符串契约**：能防漂移，但不能证明 IEC 行为；没有 PLC 仿真执行。
6. **文档漂移**：本轮已修 3 处（旧 `气缸_*` 接口说明、`气缸编号` 引用、架构文档“旧对象残留”错误结论）。

## 四、P2：上位机与交付问题

1. **超长单行模板**：`Axes.vue` 2942 字符/行、`Cylinders.vue` 1947、`Overview.vue` 921，review 和 diff 困难。
2. **store.js 职责混合**：通道选择、超时、通知、状态合并、点动停止集中在一个文件。
3. **设备模型不统一**：轴/气缸/IO 各自判断 `bound/online/alarm`，字段和文案分散。
4. **模拟器与 PLC 默认不一致**：模拟器默认绑 12 个气缸且在线，PLC 默认全未绑。演示时容易误认为“已经绑定”。
5. **打包运行限制**：WebEngine 用 `--single-process --no-sandbox --disable-gpu`（本机渲染子进程被拦截）；数据目录不可写时回退到安装目录/临时目录；单实例锁按安装目录，两个安装副本可并行。
6. **MANIFEST 曾过期**：此前仍是 343/25/47、日期 2026-11-13；已刷新为 377/27/55、2026-11-15。清单含 3038 个 `App/` 文件，但仓库此前按纯源码推送（`.gitignore` 排除 App），清单与仓库内容不一致，需要决定取舍。
7. **仓库未提交**：工作区 73 个文件未提交，远端 `main` 仍停在 `0c854a9`，与本地差异较大。

- 重建脚本可重复构建，错误门禁有效（负例验证过 70 错误阻断）。

## 六、建议顺序

1. **P0-1/P0-2**：先决定“模块在线/硬限位”的来源方式（工程开关或诊断 POU），否则现场无法动作。建议先做工程开关版，接模块后再替换为真实诊断。
2. **提交并推送仓库**：73 个文件的工作成果不能只留在本地。
3. **决定 MANIFEST 范围**：若仓库保持纯源码，清单应排除 App 或明确标注。
4. **统一模拟器与 PLC 默认绑定**，避免演示误导。
5. **再推进 P3/P4**：服务端拆分需要仿真序列测试，上位机组件化需要浏览器联调。
