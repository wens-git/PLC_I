# 气缸与真空执行器配置（协议1.3）

本次升级将手动调试和自动业务请求汇入同一气缸控制入口。物理气缸仍默认未绑定，须按现场电气图完成工程映射后才能动作。示例中文编号仅提高业务可读性，不启用输出。

## 工程配置：一缸一行

配置只有一张表，每行一个气缸，读起来就是接线表；绑定不再用位掩码，也不再维护按下标对齐的多张数组。

```st
Cy气缸配置 : ARRAY[0..53] OF 结构体_Cy气缸配置 := [
    (* CY00 双电控夹紧缸：X5/X6 传感器，Y2/Y3 阀（点号=端子号） *)
    (已绑定 := TRUE, e阀型 := Cy阀型.双线圈保持,
     out动点 := 2, out原点 := 3,
     e动点确认 := Cy确认.传感器, in动点 := 5,
     e原点确认 := Cy确认.传感器, in原点 := 6),

    (* CY01 真空带破真空：X7=真空开关；释放检测常闭，所以原点反相 *)
    (已绑定 := TRUE, e阀型 := Cy阀型.真空带破真空,
     out动点 := 6, out原点 := 7,
     e动点确认 := Cy确认.传感器, in动点 := 7,
     e原点确认 := Cy确认.传感器, in原点 := 6, 原点反相 := TRUE),

    (* 只用时间确认的推料缸：没有传感器点就省略 in 字段 *)
    (已绑定 := TRUE, e阀型 := Cy阀型.单线圈复位, out动点 := 2),

    51((已绑定 := FALSE))
];
```

- `已绑定` 决定这一缸是否参与控制，绑定掩码由程序自动汇总。
- `e阀型`：`Cy阀型.单线圈复位`、`双线圈保持`、`真空吸附`、`真空带破真空`。
- `out动点` / `out原点` 是输出点序号；单线圈和真空吸附不需要 `out原点`，可以省略。
- `e动点确认` / `e原点确认`：`Cy确认.传感器` 需要配 `in动点` / `in原点`；选 `Cy确认.延时` 就省略输入，按动作计时完成。
- `动点反相` / `原点反相` 用于常闭或反逻辑的传感器。
- 当前为**少量气缸直连模式**：点号 = 端子号（`in动点 := 5` 即 X5，`out动点 := 2` 即 Y2），实际接线在 `全局变量_物理IO.gvl.st` 与 `程序_气缸输入映射/输出映射.st`；本表点号用于 HMI 显示与配置校验，必须和接线表一致。扩展模块点从 32 起（设备树映射）。详见 [硬件IO对照表](硬件IO对照表.md)。
- 默认全部未绑定，不驱动现场输出。

程序 `程序_气缸绑定` 每扫描把这张表换算成绑定掩码和协议配置；工程值变化会清除“现场配置已确认”，需要重新确认后才能进入自动流程。

## 配置分工

PLC工程定义气缸绑定、类型、动点/原点输入与阀输出映射、输入极性和实际模块可用性。上位机只读展示这些信息，可修改动点/吸附确认延时、原点/释放确认延时和动作总超时。名称只存上位机，PLC中文编号是编译期常量，两者不会自动互相改名。

每个气缸仍占8个WORD：

|偏移|字段|作用|
|---|---|---|
|0|wiring_flags|低2位类型，bit2动点输入反相，bit3原点输入反相|
|1|move_y|动点/吸附输出编号|
|2|home_y|原点/破真空输出编号；无输出为65535|
|3|move_x|动点/真空建立检测；无传感器为65535|
|4|home_x|原点/释放检测；无传感器为65535|
|5|delay_ms|动点/吸附确认延时|
|6|timeout_ms|从动作应用开始计算的总超时|
|7|home_delay_ms|原点/释放确认延时，替代1.2未开放的调试flags|

类型0为单线圈弹簧复位，1为双线圈保持，2为真空吸附（释放时关闭吸气），3为真空吸附加破真空（释放动作期间输出破真空，完成后关闭）。模式0/2不使用原点输出；模式1/3需要独立原点输出。输入信号先按工程极性归一化，业务程序不自行取反。

## 两侧独立确认

- 有传感器：本次动作被实际应用后，目标传感器连续有效达到该侧延时才确认。信号中途失效重新计时，不能沿用上一请求的计时完成状态。
- 无传感器：从本次动作实际应用时开始，等待该侧延时后确认；上位机明确显示“延时完成”，不代表已检测到物理端位。
- 两侧可以不同，例如动点用传感器、原点用时间。
- 有传感器的延时可以为0；无传感器的延时必须大于0。两侧延时均必须小于总超时。
- 类型0回原或类型2释放时，两输出可能均为FALSE，这仍是已应用的动作，正常计时。
- 取消、故障、反向新请求清除旧的时间确认；取消不会自动变成“回原完成”。

例如动点延时200ms、原点延时800ms、超时3000ms：动点有传感器时，传感器稳定ON后再等200ms；原点无传感器时，回原输出应用后等800ms。若动点传感器迟迟不亮或不能持续有效，则从动作开始3秒后报告超时。

## 业务接口约定

业务使用设备编号常量，如 `Cy夹紧`。`Cy动点`/`Cy原点`/`Cy取消` 返回 BOOL，只表示请求已登记，不代表许可通过或动作完成；`Cy状态(设备)` 返回忙/完成/故障，自动关联该设备最近一次请求，避免把上位机手动请求或上一轮动作误认为本轮完成。每缸同一时刻由一个业务流程拥有，不应每扫描重复提交。

`Cy动点`/`Cy原点` 是业务请求；40/41 是对应网络协议码；42 是撤销输出并在故障源消失后确认历史故障。业务不直接改 Modbus 命令映像，不直接驱动 Y 输出，不伪造传感器或在线状态。

暂停、手自动切换、退出运行、自动请求待复位和上位机断线会取消当前请求的完成资格，恢复需流程显式发起新请求；默认保持已施加的保持输出，类型3破真空输出关闭。软/硬急停、全停命令9、全局复位中的停止阶段、明确撤销42、模块离线或映射无效会撤销两输出。完成后的合法延时修改不改变已施加的保持输出，新时间参数在下次动作使用。

手动模式与自动模式分开授权：上位机手动按钮只在手动模式可用，自动运行中按钮禁用并由PLC拒绝（7）；手动模式下动点/原点可直接触发，**不要求先做现场配置确认或全局复位**（参数修改引起的待复位同样不阻塞手动动作）。自动流程请求仍必须完成确认与复位。急停、故障、模块离线、映射无效和复位中仍会阻止动作，42撤销在任何模式都可用。

真空类型2/3动作超时（2140）或传感器冲突时保持吸附输出并锁存故障，等待人工42或急停释放，不会自动掉件；普通类型0/1超时撤销输出。

|事件|当前请求|输出|
|---|---|---|
|暂停、模式切换、退出运行、自动请求待复位、HMI断线|取消，恢复不重放|保持夹持/吸附，关闭类型3破真空|
|软/硬急停、全停9、取消42、模块离线/映射失效|取消|撤销两路|
|普通缸动作超时、传感器冲突、无效配置|失败并锁存故障|撤销两路|
|真空缸动作超时、传感器冲突|失败并锁存故障|保留已施加的吸附输出，关闭类型3破真空；不自动恢复吸附|
|完成后修改合法延时|不启动新动作|保持原输出|

42的物理含义随类型不同：类型0断电动点线圈即弹簧回原点；类型1双电控两线圈失电只是阀保持，**不能停止已在运动的气缸**；类型2关闭吸气释放工件；类型3同时撤销破真空。上位机按钮按类型显示对应文字。

输出撤销不保证机械制动或保持载荷，夹持/真空设备需要现场独立安全回路。该实现不是安全PLC功能。

## 物理IO映射层

气缸地址不再是“填了就会动”的摆设，而是经过一层显式映像：

| 环节 | 位置 | 说明 |
|---|---|---|
| 输入映像 | `aw气缸输入映像`, 7 WORD | 设备树把扩展输入模块映射到此数组，容量112点 |
| 输出映像 | `aw气缸输出映像`, 4 WORD | 设备树把扩展输出模块映射到此数组，容量56点 |
| 模块在线 | `b气缸输入模块在线` / `b气缸输出模块在线` | 真实模块诊断；未接诊断时由工程开关决定 |
| 工程开关 | `b气缸IO已接入` / `b气缸IO模块诊断已接入` | 未接诊断前以开关为准，接入后以真实在线位为准 |
| 输入映射 | `程序_气缸输入映射` | 按绑定结果读出两侧传感器，推导映射有效/模块就绪 |
| 输出映射 | `程序_气缸输出映射` | 按绑定结果写阀输出，未绑定或无效时清0 |
| 绑定换算 | `程序_气缸绑定` | 每扫描把一缸一行的工程表换算成绑定掩码与发布配置 |

`ab气缸映射有效` 由绑定、配置有效和地址容量推导，不再允许手工置TRUE；模块未映射时气缸保持离线且许可关闭，输出映像全0。主循环顺序固定为：气缸绑定 → 服务端 → 输入映射 → 气缸调度 → 输出映射。内建点表、气缸点命名和端子对照见 [硬件IO对照表](硬件IO对照表.md)。

轴侧：硬限位输入未接线时（`b硬限位已接线 := FALSE`），软限位必须保持启用，否则运动类命令被拒绝，避免软硬限位同时失效。清故障命令23只消除报警，**不再自动使能**，使能必须单独下发20。

绑定纪元随 `w已绑定轴` / `lw已绑定气缸` 变化自动递增，上位机因此能发现硬件档案变化。监控快照仍每300ms发布一次，界面状态最多滞后0.3秒，这不影响控制扫描。

## 业务代码示例

在与主循环相同的控制任务中使用，业务步骤在气缸调度前提交；调度每扫描只调用一次。请求号和步骤不得PERSISTENT/RETAIN跨PLC重启恢复。正式自动流程开关仍需在工艺接入后启用，不能用示例绕过运行、复位和许可条件。

```iecst
VAR
    步骤 : UINT;
    状态 : 结构体_Cy状态;
END_VAR

CASE 步骤 OF
    10:
        IF Cy动点(Cy夹紧) THEN
            步骤 := 20;
        ELSE
            (* 本次提交未登记：按工艺拒绝处理，不要无限自动重试。 *)
            步骤 := 900;
        END_IF;
    20:
        状态 := Cy状态(Cy夹紧);
        IF 状态.w故障 <> 0 THEN
            步骤 := 900;
        ELSIF 状态.b完成 THEN
            步骤 := 30;
        END_IF;
    30:
        (* 夹紧本轮确认完成，进入下一道业务。 *)
    900:
        (* 由工艺统一处理停止、夹持和复位，不能每扫描重新提交停止。 *)
END_CASE;
```

- `Cy动点(设备)` / `Cy原点(设备)` / `Cy取消(设备)` 返回 BOOL：TRUE 表示请求已登记，不代表完成。
- `Cy状态(设备)` 返回忙/完成/故障，自动关联该设备最近一次请求，业务不需要自己保存请求号。
- `Cy状态.w故障`：0 正常，15 无请求/参数非法，19 请求失效或取消，其它值见拒绝与报警表。
- 端位状态仍看 `Runtime.ast气缸[i]` 的 `b在动点` / `b在原点`，用于互锁；无传感器侧是时间确认。
- 设备编号常量在 `全局变量_Cy设备.gvl.st`（示例 `Cy夹紧`、`Cy定位`），命名与现场绑定无关。

实际工程表位于 `plc/src/hardware/全局变量_气缸工程.gvl.st`（一缸一行 `Cy气缸配置`）。当前不启用现场气缸。绑定、阀型和前五字会同步到保持配置和上位机，模块就绪必须接真实诊断，不能直接用绑定常量代替。

## 协议升级与迁移

签名由0x584A5632变为0x584A5633。新上位机与旧PLC互相不兼容，必须配套升级；不能为了连通而跳过签名检查。寄存器总量不变。

PLC可识别旧1.2保持区，保留已有轴与点位数据，将旧气缸未开放flags转换为原点延时，清除配置确认。接线和类型重新以工程配置为准，不能继承未知旧位后直接开放动作。模拟持久化独立迁移，不代表真实PLC保持区验收。

## 现场接入步骤

1. 按电气图改 3 个地方：① [全局变量_物理IO.gvl.st](../plc/src/hardware/全局变量_物理IO.gvl.st) 声明该缸的命名 X/Y 信号；② [程序_气缸输入映射.st](../plc/src/hardware/程序_气缸输入映射.st)/[程序_气缸输出映射.st](../plc/src/hardware/程序_气缸输出映射.st) 末尾各加一行；③ [全局变量_气缸工程.gvl.st](../plc/src/hardware/全局变量_气缸工程.gvl.st) 填一缸一行（`已绑定`、`类型`、点号/确认方式），未接的输入保持 65535 或选 `Cy确认.延时` 省略。模板与接线对照见 [硬件IO对照表](硬件IO对照表.md)。
2. **内建直连点不需要设备树映射**，由输入/输出映射程序末尾的直连行直接读写命名 BOOL；**只有扩展模块**需要在设备树把模块映射到 `aw气缸输入映像[2..6]` / `aw气缸输出映像[2..3]`（点 32 起，word0/word1 不用），并把模块诊断接到两个在线位；未映射前扩展气缸保持离线，许可关闭。
3. 核对工程映射、模块在线反馈及两侧输入有效极性，无传感器侧设置合理动作时间。
4. 用配套源码离线重建PLC工程，检查编译记录，再在现场按既有流程部署。本次自动化不连接或下载PLC。
5. 上位机核对类型、传感器/延时确认方式，分别验证两方向、滤波、超时、取消、手自动切换和暂停恢复；真空缸必须验证超时保持吸附与手动释放。
6. 轴侧确认硬限位是否真实接线；未接线时保持软限位启用，清故障后需单独使能。
7. 无传感器或无真空检测的模式无法检测卡缸、漏气、吸附失败，工艺需要此保证时应使用真实检测信号。
