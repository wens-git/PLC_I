# 气缸与真空执行器配置（协议1.3）

本次升级将手动调试和自动业务请求汇入同一气缸控制入口。物理气缸仍默认未绑定，须按现场电气图完成工程映射后才能动作。示例中文编号仅提高业务可读性，不启用输出。

## 配置分工

PLC工程定义气缸绑定、类型、动点/原点输入与阀输出映射、输入极性和实际模块可用性。上位机只读展示这些信息，可修改动点/吸附确认延时、原点/释放确认延时和动作总超时。名称只存上位机，PLC中文编号是编译期常量，两者不会自动互相改名。

每个气缸仍占8个WORD：

|偏移|字段|作用|
|---|---|---|
|0|wiring_flags|低2位类型，bit2动点输入反相，bit3原点输入反相|
|1|move_y|动点/吸附输出编号|
|2|home_y|原点/破真空输出编号；无输出为65535|
|3|move_x|动点/真空建立检测；无传感器为65535|
|4|home_x|原点/释放检测；无传感器为65535|
|5|delay_ms|动点/吸附确认延时|
|6|timeout_ms|从动作应用开始计算的总超时|
|7|home_delay_ms|原点/释放确认延时，替代1.2未开放的调试flags|

类型0为单线圈弹簧复位，1为双线圈保持，2为真空吸附（释放时关闭吸气），3为真空吸附加破真空（释放动作期间输出破真空，完成后关闭）。模式0/2不使用原点输出；模式1/3需要独立原点输出。输入信号先按工程极性归一化，业务程序不自行取反。

## 两侧独立确认

- 有传感器：本次动作被实际应用后，目标传感器连续有效达到该侧延时才确认。信号中途失效重新计时，不能沿用上一请求的计时完成状态。
- 无传感器：从本次动作实际应用时开始，等待该侧延时后确认；上位机明确显示“延时完成”，不代表已检测到物理端位。
- 两侧可以不同，例如动点用传感器、原点用时间。
- 有传感器的延时可以为0；无传感器的延时必须大于0。两侧延时均必须小于总超时。
- 类型0回原或类型2释放时，两输出可能均为FALSE，这仍是已应用的动作，正常计时。
- 取消、故障、反向新请求清除旧的时间确认；取消不会自动变成“回原完成”。

例如动点延时200ms、原点延时800ms、超时3000ms：动点有传感器时，传感器稳定ON后再等200ms；原点无传感器时，回原输出应用后等800ms。若动点传感器迟迟不亮或不能持续有效，则从动作开始3秒后报告超时。

## 业务接口约定

业务使用中文编号，如气缸编号.夹紧缸。提交接口返回UDINT请求号，0代表未登记；登记不等于许可通过或动作完成。保存请求号，随后以缸号和请求号查询忙、完成、故障，避免上位机手动请求或前一轮动作被误认为本轮完成。每缸同一时刻由一个业务流程拥有，不应每扫描重复提交。

气缸_到动点/气缸_到原点是业务请求；40/41是对应网络协议码；42是撤销输出并在故障源消失后确认历史故障。业务不直接改Modbus命令映像，不直接驱动Y输出，不伪造传感器或在线状态。

暂停、手自动切换、退出运行、待复位和上位机断线会取消当前请求的完成资格，恢复需流程显式发起新请求；默认保持已施加的保持输出，类型3破真空输出关闭。软/硬急停、全停命令9、全局复位中的停止阶段、明确撤销42、模块离线或映射无效会撤销两输出。完成后的合法延时修改不改变已施加的保持输出，新时间参数在下次动作使用。

|事件|当前请求|输出|
|---|---|---|
|暂停、模式切换、退出运行、待复位、HMI断线|取消，恢复不重放|保持夹持/吸附，关闭类型3破真空|
|软/硬急停、全停9、取消42、模块离线/映射失效|取消|撤销两路|
|动作超时、传感器冲突、无效配置|失败并锁存故障|撤销两路|
|完成后修改合法延时|不启动新动作|保持原输出|

输出撤销不保证机械制动或保持载荷，夹持/真空设备需要现场独立安全回路。该实现不是安全PLC功能。

## 业务代码示例

在与主循环相同的控制任务中使用，业务步骤在气缸调度前提交；调度每扫描只调用一次。请求号和步骤不得PERSISTENT/RETAIN跨PLC重启恢复。正式自动流程开关仍需在工艺接入后启用，不能用示例绕过运行、复位和许可条件。

```iecst
VAR
    步骤 : UINT;
    夹紧请求 : UDINT;
    故障码 : WORD;
END_VAR

CASE 步骤 OF
    10:
        夹紧请求 := 气缸_到动点(缸号 := 气缸编号.夹紧缸);
        IF 夹紧请求 = 0 THEN
            (* 本次提交未登记，走工艺拒绝处理；不要无限自动重试。 *)
            步骤 := 900;
        ELSE
            步骤 := 20;
        END_IF;
    20:
        故障码 := 气缸_故障(缸号 := 气缸编号.夹紧缸, 请求号 := 夹紧请求);
        IF 故障码 <> 0 THEN
            步骤 := 900;
        ELSIF 气缸_完成(缸号 := 气缸编号.夹紧缸, 请求号 := 夹紧请求) THEN
            步骤 := 30;
        END_IF;
    30:
        (* 夹紧本轮确认完成，进入下一道业务。 *)
    900:
        (* 由工艺统一处理停止、夹持和复位，不能每扫描重新提交停止。 *)
END_CASE;
```

原点请求使用气缸_到原点；气缸_取消返回新的请求号，但取消不是到位成功，不会产生完成。气缸_故障返回WORD错误码：0无错误，15非法参数/请求号0，19请求失效或取消，其它值见拒绝与报警表。提交返回0时没有新请求号，不应把旧请求错误当成本次提交原因。

实际工程表位于 `plc/src/02_gvl/全局变量_气缸工程.gvl.st`，中文编号位于 `气缸编号.gvl.st`。当前都不启用现场气缸。类型与四个映射数组前五字会同步到保持配置和上位机，模块就绪必须接真实诊断，不能直接用绑定常量代替。

## 协议升级与迁移

签名由0x584A5632变为0x584A5633。新上位机与旧PLC互相不兼容，必须配套升级；不能为了连通而跳过签名检查。寄存器总量不变。

PLC可识别旧1.2保持区，保留已有轴与点位数据，将旧气缸未开放flags转换为原点延时，清除配置确认。接线和类型重新以工程配置为准，不能继承未知旧位后直接开放动作。模拟持久化独立迁移，不代表真实PLC保持区验收。

## 现场接入步骤

1. 按电气图填写实际使用的气缸编号、模式和I/O，未接的输入/输出保持65535；不把槽位容量当成现场数量。
2. 核对工程映射、模块在线反馈及两侧输入有效极性，无传感器侧设置合理动作时间。
3. 用配套源码离线重建PLC工程，检查编译记录，再在现场按既有流程部署。本次自动化不连接或下载PLC。
4. 上位机核对类型、传感器/延时确认方式，分别验证两方向、滤波、超时、取消、手自动切换和暂停恢复。
5. 无传感器或无真空检测的模式无法检测卡缸、漏气、吸附失败，工艺需要此保证时应使用真实检测信号。
